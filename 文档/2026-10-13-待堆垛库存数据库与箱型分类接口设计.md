# 待堆垛库存数据库与箱型分类接口设计

## 概述

当前 Core 已能维护规划箱集合、业务状态和快照，但缺少一套面向“待堆垛库存”的独立数据域。Program 侧现在只能把箱子直接转成规划输入，无法在 Core 内沉淀“库存事实数据 + 箱型分类结果”，导致以下问题：

1. 同一批货架箱数据在 Program 和 Core 之间重复转换，口径不一致风险高。
2. 箱型分类算法散落在脚本/工具侧，结果不可复用、不可追溯。
3. 规划与库存没有清晰边界，后续要做库存过滤、箱型占比、规则选型会持续堆复杂度。

本设计在 StackPlanner.Core 内新增库存数据库模块，提供两类接口：

1. 入库接口：Program 把读取到的 RackBox 数据写入 Core 库存数据库。
2. 查询接口：Program 从 Core 获取箱型分类结果（按 length/height/depth 语义，20mm 容差）。

## 目标与非目标

### 目标

1. 在 Core 内新增“待堆垛库存数据库”，独立于当前规划器箱集合。
2. 内置箱型分类算法，按长/高/宽分别比较，容差默认 20mm。
3. Program 可通过稳定接口写入库存、读取分类结果。
4. 结果可用于后续规划选箱，但本阶段不强耦合到 GeneratePlan 主流程。

### 非目标

1. 本阶段不引入外部关系型数据库（SQLite/SQL Server）。
2. 本阶段不改造机械执行链路和状态机语义。
3. 本阶段不做跨进程持久化恢复（可在下一阶段扩展到快照）。

## 总体方案

### 路线选择

采用“Core 内存数据库 + 明确查询接口”的路线，不直接上外部 DB。

选择原因：

1. 与当前 Core 的内存状态模型一致（现有 status-server 已是纯内存）。
2. 改动面可控，不影响现有规划与状态更新主链路。
3. 后续若要持久化，可在同一数据模型上追加快照字段，不推翻接口。

### 模块划分

1. InventoryDatabase：库存数据表（内存）与索引。
2. BoxTypeClassifier：箱型分类服务（20mm 容差，按 L/H/D）。
3. InventoryFacade（挂在 StackPlanner）：对外统一入口，Program 不直接操作内部表结构。

## 数据模型设计

新增到 StackPlanner.Core.Contracts.cs：

1. InventoryBoxRecord
   - BoxNumber: string
   - LengthMm: double
   - HeightMm: double
   - DepthMm: double
   - WeightKg: double
   - Source: string（如 RackBox）
   - UpdatedAtUtc: DateTimeOffset

2. BoxTypeClusterSummary
   - TypeId: string（如 BT-0001）
   - Count: int
   - RepLengthMm: double
   - RepHeightMm: double
   - RepDepthMm: double
   - WeightAvgKg: double
   - WeightMinKg: double
   - WeightMaxKg: double

3. BoxTypeClassificationResult
   - ToleranceMm: double
   - TotalBoxes: int
   - ClusterCount: int
   - Clusters: IReadOnlyList<BoxTypeClusterSummary>
   - GeneratedAtUtc: DateTimeOffset

4. InventoryUpsertResult
   - Upserted: int
   - Inserted: int
   - Updated: int
   - Invalid: int
   - Message: string

## 箱型分类算法

### 规则

1. 使用原始语义：length/height/depth，不做大中小边重排。
2. 两箱同类判定：
   - |Δlength| <= tolerance
   - |Δheight| <= tolerance
   - |Δdepth| <= tolerance
3. 默认 tolerance = 20mm，可由调用方覆盖。

### 计算流程

1. 从 InventoryDatabase 取当前有效箱记录。
2. 按 (LengthMm, HeightMm, DepthMm, BoxNumber) 排序，保证计算确定性。
3. 使用并查集计算连通分量（等价于 Chebyshev 距离阈值聚类，阈值 20mm）。
4. 每个分量输出一条 BoxTypeClusterSummary；代表尺寸取算术均值。
5. Cluster 按 Count 降序输出，Count 相同按代表尺寸字典序升序。

说明：该方案对输入顺序不敏感，避免“逐条吸附聚类”导致的顺序依赖。

## Core 接口设计

在 StackPlanner 类新增公开方法：

1. UpsertInventoryBoxes(IEnumerable<InventoryBoxRecord> boxes, bool replaceAll = false)
   - 写入库存数据库。
   - replaceAll=true 时先清空后重建（适合整批 RackBox 覆盖写）。

2. GetInventoryBoxes()
   - 返回库存数据只读副本。

3. ClassifyInventoryBoxTypes(double toleranceMm = 20)
   - 返回 BoxTypeClassificationResult。

4. ClearInventoryBoxes()
   - 清空库存数据库。

定位建议：

1. StackPlanner.cs
   - 在 CreateSnapshot()/RestoreSnapshot() 相邻区域增加库存 API。
2. Contracts.cs
   - 在 Box/BoxGroup 相关模型后增加库存与分类结果模型。
3. 新增 InventoryDatabase.cs
   - 封装库存增删改查与主键校验。
4. 新增 BoxTypeClassifier.cs
   - 只做分类，不依赖规划状态。

## Program 接口设计

在 Mujuco/tests/StackPlannerTests/Program.cs 的 status-server 模式扩展 action：

1. replace-inventory
   - 入参：RackBox 数据（支持原始 JSON 字典格式）。
   - 行为：映射到 InventoryBoxRecord，调用 UpsertInventoryBoxes(replaceAll=true)。

2. upsert-inventory
   - 入参：库存增量列表。
   - 行为：调用 UpsertInventoryBoxes(replaceAll=false)。

3. get-inventory-types
   - 入参：可选 toleranceMm，默认 20。
   - 行为：调用 ClassifyInventoryBoxTypes，返回分类结果。

4. get-inventory
   - 返回当前库存记录，便于 Program 做二次校验。

### 输入映射规则（RackBox -> InventoryBoxRecord）

1. boxNumber = 顶层 key。
2. lengthMm = length * 1000。
3. heightMm = height * 1000。
4. depthMm = depth * 1000。
5. weightKg = weight。
6. 任一尺寸 <= 0 或非数字，计入 Invalid，不写入库存。

## 与现有规划流程的关系

1. 库存数据库与当前 _group（规划箱集合）解耦。
2. 规划入口 GeneratePlan() 保持现状，不隐式读取库存数据库。
3. Program 可按业务策略从分类结果中挑选箱子，再调用现有 AddBox/AddBoxes 进入规划。
4. 后续如需自动选箱，可新增 BuildPlanningSetFromInventory()，本阶段不纳入。

## 兼容性与演进

1. 现有 status-server 动作（update/get-snapshot/replace-snapshot/clear）保持兼容。
2. 新增动作不影响旧调用方。
3. 下一阶段可把库存数据库并入 PlannerSnapshot（SchemaVersion 升级到 2，兼容读取 1）。

## 实施步骤

1. Core 合同层：在 Contracts.cs 增加库存与分类 DTO。
2. Core 存储层：新增 InventoryDatabase.cs。
3. Core 算法层：新增 BoxTypeClassifier.cs（20mm 容差）。
4. Core 门面层：在 StackPlanner.cs 增加库存相关公开方法。
5. Program 接口层：扩展 RunStatusServer() 的 action 分派。
6. Program 映射层：新增 RackBox JSON 解析与单位转换。
7. 测试：
   - Core 单测：分类正确性、顺序无关性、容差边界。
   - Program 集成测试：replace-inventory + get-inventory-types 闭环。

## 验收标准

1. Program 可把整份 RackBox 数据一次性写入 Core 库存数据库。
2. Core 返回的分类结果遵循 L/H/D 语义与 20mm 容差。
3. 同一输入重复调用，分类结果稳定一致。
4. 不影响现有规划与状态服务的既有能力。
5. 对无效尺寸数据有明确统计与错误信息。
